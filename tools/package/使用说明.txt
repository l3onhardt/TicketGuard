票审 TicketGuard 试用版 —— 使用说明
====================================

这是什么
--------
配电第一种工作票的离线预审工具。把票面交给它，它对照典票库列出“疑似问题”，
每条都写明依据。它只做预审建议，是否接收或打回由审票人决定。
不联网，不用安装任何东西，删掉这个文件夹就是卸载。


怎么用
------
1. 双击“票审.exe”。
   会出现一个黑色的窗口，同时浏览器自动打开“票审”的页面。
   黑色窗口就是程序本身，用的时候不要关它。
   （浏览器没有自动打开的话，把黑色窗口里那行 http://127.0.0.1 开头的地址
   复制到浏览器的地址栏。）

2. 在页面上放入票面：
   在系统里把票面全文选中、复制，粘贴到页面的大框里；
   或者点“选择 .txt 文件”，或者把 .txt 文件拖进大框（可以一次几张）。
   手头没有票，可以点页面上的示例票试一试，它们都是编造的。

3. 选模式，点“开始预审”。报告直接显示在页面里。

4. 看完点“再审一张”。全部用完，点右上角“退出票审”，或者直接关掉黑色窗口。

报告同时保存在这个文件夹的“报告”文件夹里，页面上方写着具体位置。


两种模式有什么不一样
--------------------
规则模式   只用规则查。一两秒出结果，同一张票每次结果都一样。任何电脑都能用。
模型模式   规则查完以后，再请这台电脑上的小模型把“疑似缺少措施”的事项复核一遍。
           第一张票要等模型启动（十几秒到一分钟），之后每张票十几秒。
           需要 Windows 10 或更新的系统、8GB 内存，并且这个文件夹里有 models 文件夹。
           模型已经放在文件夹里，不用另外安装。

模型不会自己找问题，也不会删掉规则找到的问题。它只做一件事：
规则说“典票上有这类措施、票面上没找到”的时候，模型把典票那条措施和票面同一栏的
每条措施逐条比一遍，判断是不是同一类措施、只是写法不同。

  - 模型认为票面上有：这一条从“疑点”降为“提示”，标题变成“某栏有一条措施的写法和典票不同”，
    下面写着“模型的看法”，指出它认为票面上的哪一条对得上。请你看一眼确认。
  - 模型认为没有，或者把握不够：这一条照旧是疑点，和规则模式一样。

所以模型模式的疑点只会比规则模式少，不会多。提示默认不进打回草稿，但都还在页面上。

这台电脑用不了模型模式时，页面上“模型模式”是灰的，并写着原因。
模型中途没有用成时，报告照常按规则出，页面和报告里都会写明原因。


报告怎么读
----------
从上往下读：

1. 最上面：这是哪张票（票号、计划时间、负责人、工作地点和任务）。
2. 彩色的结论条：机器查出了什么。它不会说“合格”或“通过”。
3. 机器查了什么：一张清单。
     “已查，无疑点”  查过了
     “需要确认”      下面有具体事项
     “机器没查”      机器没有查，需要你自己审
   其中“模型复核”一行写着这次有没有请模型、问了几条。
4. 需要确认的事项：每条写明问题、票面上怎么写的、典票上怎么写的、依据哪一条。
   确认属实的就勾上“写进打回意见”。
5. 打回意见草稿：由勾选的事项拼成，可以直接改，点“复制草稿”就能贴走。
6. 对照的典票场景：机器是拿哪个典票场景来比的，像不像（高 / 中 / 低）。
   如果你觉得这张票不是这个场景，措施比对那一项就不作数。
7. 给开发者的反馈：见下一节。


请帮忙反馈（这是这次试用最重要的事）
------------------------------------
每看完一张票的报告，请顺手：

1. 在每条事项下面选“属实 / 误报 / 说不清”。
2. 在报告最下面选“对照的典票场景对不对”。
3. 机器漏掉的问题、看不懂的地方，写在“补充说明”里。
4. 点“复制反馈”，粘贴到一个文本文件里攒着，最后一起交给开发者。

复制出来的文字里只有事项的类别和你的选择，没有票面内容。
补充说明里请不要写真实的人名、线路名、设备名和票号。

试用一段时间以后，再请填一下“反馈表.txt”里的几个总体问题。

漏报比误报严重：你一眼看出、但报告没报的问题，请一定记下来。


这个版本的边界
--------------
- 只覆盖配电第一种工作票，对照 21 个典票场景。典票库里没有的作业，措施不做比对。
- 只接受票面文本（粘贴，或 .txt 文件）。Word、Excel、PDF 不能直接放进来：
  请打开它，全选、复制，粘贴到页面里。
- 查不了：现场安全距离和隔离是否有效、设备名称和编号是否写对、票种是否选对。
- 规则库和典票模板还没有经过业务人员逐条核对，所以规则类的发现暂时都只算“提示”。
- 模型只认得出一部分换了说法的措施（在编造的测试票上是两到四成）。认不出的照旧报疑点，
  请人工排除。在同样的测试票上，模型没有把真正缺少的措施放过去，但测试票不是真实票，
  所以降为“提示”的事项也请看一眼。
- 规则认为“有”的措施不会再问模型。票面上同一栏里别的措施碰巧含有同样的关键词时，
  两种模式都可能漏报。
- 模型模式在 Windows 7 上用不了（模型程序需要更新的系统）。Windows 7 上请用规则模式。
- 页面还没有在 Windows 7 和 IE 浏览器上实际试过。打不开或者显示不对，请记到反馈表里。


数据安全
--------
- 程序不联网。那个页面只有这台电脑自己能打开，别的电脑连不上；地址里带着一串
  每次都不一样的口令，这台电脑上别的程序也用不了它。
- 模型模式下，程序会在本机启动一个模型程序（llama-server.exe），两者只在本机内部通信，
  退出票审时一起关掉。
- “报告”文件夹里的报告带着票面内容。真实票面和报告请只放在内网电脑上，不要拷出内网，
  不要发给任何人或任何在线工具，包括开发者。反馈只需要“复制反馈”里的那段文字。


还可以这样用
------------
把 .txt 文件直接拖到“票审.exe”的图标上，也能出报告（报告生成在票的旁边）。
