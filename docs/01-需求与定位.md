# 01 需求与定位

## 1. 背景

配电作业前要开具工作票。审票的人（运维单位的接收人、许可人，以及生技部、安监部的抽查人员）需要逐张核对票面：

- 票种选得对不对；
- 安全措施有没有漏项；
- 人员资格、时间、签名流程是否合规。

南宁供电局在 2026 年 9 月发布了《配电运检、配电自动化两票典型票库（2026 版，试行）》，覆盖约 135 个典型场景，并把常见违章点和对应的安规条款写进了脚注。

审票目前全靠人工经验。漏审的后果很重：典票库脚注写明，被查出不合格票会触发季度安全奖否决。审票也很耗时，而且不同人的审查尺度不一致。

## 2. 目标用户（已确定）

| 角色 | 场景 | 对系统的诉求 |
|---|---|---|
| **主要用户：运维单位的工作票接收人、许可人** | 收到作业单位提交的工作票后，决定接收还是打回 | 快速看到疑似问题和依据，方便写打回理由 |
| 次要用户：生技部、安监部抽查人员 | 批量抽查已执行的票，评定票面合格率 | 批量处理、能导出统计结果 |
| 间接受益：作业单位的工作负责人、签发人 | 开票时自查（以后可以开放给他们用） | 提交前就发现问题，减少被打回 |

> 定位已确认（2026-11-05）：需求方在**设备运维单位**。

### 需求方提出的高频问题（按优先级排序）

需求方点名了四类最常见的问题，第一期优先覆盖：

| # | 问题 | 对应检查维度 | 第一期能做到的程度 |
|---|---|---|---|
| 1 | **工作地点错误** | B 格式 + E 一致性 | 能查：缺少双重名称或杆号；工作地点的线路或站名与停电范围、安全措施对不上；杆号不在接地封闭范围内（杆号能比较时）。**查不了**：地点写成了另一个真实存在的设备，而票面其他地方都跟着写错。这需要设备台账，第一期没有 |
| 2 | **安全措施漏项或写错** | E 措施比对 | 主要战场：对照典票场景逐条比对。“写错”包括：接地位置的大号侧和小号侧写反、该拉开的开关写成了别的开关、二次回路措施不完整 |
| 3 | **人员数量不符** | D 人员规则 | 能查全：总人数 = 1 + 工作班成员数；人员变更后人数是否仍然一致；分组派工单的人数 |
| 4 | **票种选错** | A 票种选择 | 依据作业内容和安规中选票的条款判断应该用哪种票（规则加模型）；第一期只区分第一种票、第二种票和书面布置记录票 |

## 3. 核心用户故事

1. 作为接收人，我在系统里把工作票**打印成 PDF**（系统不能导出，但能打印），把 PDF 拖进本工具，**10 秒内**看到一份报告：这张票对应哪个典票场景，有哪些疑似问题，每个问题依据哪一条条款。
2. 作为接收人，我能看到每个问题的置信度。高置信、属于硬规则的问题标红，低置信的问题标黄，提醒我自己再核对。
3. 作为接收人，我能一键把报告里勾选的问题生成“打回意见”文本，复制到系统里。打回这个动作由我自己执行。
4. 作为抽查人员，我把一批导出的票放进一个文件夹，得到一份汇总表：每张票的问题数、问题类型分布。
5. 作为维护人员，典票库或安规更新时，我只改 `data/rules`、`data/templates` 里的 JSON，不用改代码。

## 4. 范围

### 第一期要做

- **票种**：先做配电第一种工作票（21 个场景）。之后依次扩展到第二种票、紧急抢修票、书面布置记录票、动火票、带电作业票、操作票。
- **检查维度**：
  - A. **票种选择**：作业内容和安全距离对应的票种是否正确。
  - B. **必填项与格式**：比如设备是否写了双重名称、是否注明起止杆号、编号格式。
  - C. **时间逻辑**：签发时间早于接收时间，接收时间早于许可时间；有效期；延期办理时限。
  - D. **人员规则**：不得兼任的角色；需要设专责监护人的情形；代签格式。
  - E. **安全措施完整性**：对照典票场景，检查应拉开的开关、二次回路、接地线、标志牌、可能来电的电源（光伏、储能、发电机）有没有漏项。
  - F. **风险预警项**：典票里标注“风险预警”和“易出现违章”的要点。
- **输出**：本地 HTML 报告和 JSON 结果，以及命令行工具。

### 明确不做（非目标）

- **不连接生产系统**：不抓包，不爬取，不模拟登录。只有立项并拿到正式接口授权后，才会对接系统。
- **不自动打回，不自动认定违章**。
- **不判断现场物理条件**：比如实际安全距离、所拉的开关能否真正隔离作业区。这些需要配网拓扑、GIS 和现场勘察。报告里要明确写出这条局限。
- **不核验人员资质的真实性**：这需要智慧安监系统的数据。第一期只做“资质栏是否填写、格式是否完整”。
- **不生成工作票**：生成票是另一个方向，以后可以评估。

## 5. 运行约束

| 项 | 约束 |
|---|---|
| 硬件 | i5 四核、8GB 内存、无独立显卡 |
| 系统 | Windows 10 / 11 x64（同时要验证 Windows 7 能否运行，待确认） |
| 网络 | 完全离线 |
| 安装 | 单文件 exe 加一个模型文件，不需要管理员权限，不需要安装 Python |
| 单票耗时 | ≤ 10 秒（P95） |
| 内存占用 | ≤ 2.5GB（包括模型） |

## 6. 成功标准

具体的指标定义见 `06-评测与验收.md`，这里只列最关键的四条：

- 135 个典票全部零误报。典票本身就是标准答案，不能报错。
- 在合成的缺陷票上，硬规则类问题检出率 100%，安全措施漏项检出率 ≥ 95%。
- 在人工核验的黄金集上，标红（error）问题的精确率 ≥ 90%，也就是说审票人不会被大量误报烦到不想用。
- 拿到单位内部立项（职工创新、QC 小组或信息化项目），并通过信息部门的安全审查。
