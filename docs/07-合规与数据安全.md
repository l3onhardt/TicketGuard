# 07 合规与数据安全

## 1. 基本立场

这个项目最大的风险不在技术，而在合规。任何一条下面的红线被踩到，项目都会直接终止，还可能让需求方个人承担责任。

## 2. 红线与理由

| 红线 | 理由 |
|---|---|
| 不抓包、不爬取、不逆向生产系统 | 违反公司网络安全管理规定，属于未授权获取信息系统数据（情节严重的可能触及《刑法》第 285 条）；而且这样做出来的东西不可能通过安全审查 |
| 真实工作票不出内网，不发给任何 AI（境内境外都一样） | 生产数据外泄；包含人员个人信息 |
| 不在内网终端私自安装软件、私自拷贝模型文件 | 违反终端准入和软件白名单管理规定 |
| AI 不自动打回、不自动认定违章 | 按安规第 5.3 条，票面正确性由负责人、签发人、接收人、许可人分别负责；认定违章会影响考核和奖金（典票库脚注写明会否决季度奖），必须由人来确认 |
| 不使用境外模型 API（包括作为蒸馏教师） | 数据出境；还可能违反对方服务条款 |

### 关于“抓包可以导出”（2026-11-05 讨论记录）

技术上能抓到，不等于允许抓。打印是业务上本来就允许的操作，打印成 PDF 拿到的数据和抓包拿到的一样，而且不留任何违规痕迹。所以：**打印成 PDF 是正路，抓包永远不做**。

以后如果嫌每次打印麻烦，正确的升级方式是立项后申请正式接口，而不是抓包。

打印成 PDF 时要注意：PDF 只能存放在内网电脑上，不能拷出内网，处理完就可以删除（本工具读取后不会另外保存原票）。

## 3. 正确的落地路径

1. **外网原型阶段（当前）**：只用典票库和合成数据，在个人电脑上开发，证明技术上可行。
2. **立项**：以职工创新、QC 小组、创新工作室或信息化需求的名义申报。要准备的材料有：需求说明（`01`）、架构（`02`）、评测报告（`06`）、本文件。
3. **安全审查**：交给信息部门审查源代码、依赖清单（标准库加 llama.cpp）和模型来源（开源底座的许可证和出处）。重点说明“零联网、零外部依赖、只读文件输入”。
4. **内网部署和试运行**：通过正规介质导入，先在一个班组试点，和人工审票双轨并行。
5. **内网评测**：用真实历史票（包括被打回的票）做评测和微调，数据始终不离开内网。
6. **（可选）系统对接**：由信息部门提供正式接口，替代手动导出。

## 4. 开发过程中的数据处理

- `data/raw/` 被 git 忽略。典票库的原始文件只留在本机。
- 前言里的编审人员实名名单不得进入模板、样本、测试和日志。
- 向 AI 编码助手提问时，只提供合成样本或编造的片段。
- 如果需求方今后提供真实票的问题描述，只接受**口述或改写后**的模式描述（比如“常见问题：漏写某类接地”），不接受原票。
