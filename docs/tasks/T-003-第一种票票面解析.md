## 目标

把一张配电第一种工作票的“票面文本”解析成 `schema.Ticket`。票面文本的格式见 `ingest/source.py` 的模块说明，样例见 `tests/fixtures_d1.py`（两张合成票，覆盖了典票库里出现过的各种写法变体）。

## 接口（照写）

```python
# src/ticketguard/ingest/ticket_parser.py
def parse_datetime(s: str) -> str | None: ...   # 在 s 中找第一个“YYYY年M月D日H时M分”，返回 "YYYY-MM-DDTHH:MM"
def ticket_block(text: str) -> str: ...          # 从输入中截出这一张票的票面
def parse_dist1(text: str) -> Ticket: ...        # 票面文本 → Ticket（ticket_type=DIST_1，raw_text=ticket_block 的结果）
```

在 `ingest/__init__.py` 中导出 `parse_dist1`、`parse_datetime`。

## 规则（由规划者确定，不要改）

下文中“空白”指半角空格和全角空格 `　`；“单元格”指一行按 `|` 拆开后、去掉两端空白的各段。

**截取票面 `ticket_block`**
1. 从第一个“去掉行首空白后以 `编号：` 开头”的行开始，到这一行之后第一个 `[TABLE]` 行所对应的第一个 `[/TABLE]` 行为止（含两端）。这样会排除票后附带的派工单等内容。
2. 找不到 `编号：` 行，或其后没有 `[TABLE]`，抛 `ValueError`，消息用中文说明缺什么。

**必备栏目**：票面里缺少以下任一标签，抛 `ValueError("票面缺少栏目：<标签>")`：`工作负责人（监护人）：`、`工作地点或设备（注明`、`停电设备或线路名称：`、`调度或设备运维单位负责的安全措施`、`工作班组自行装设的接地线`。其余字段缺失时填 `None`（或不产生对应的 Person / 措施）。

**表头**（都在含 `工作负责人（监护人）：` 的那一行里；“取到下一个 `/` 为止”指截到下一个 `/` 之前并去掉两端空白）
3. `number`：`编号：` 之后去掉空白。
4. 工作负责人：`工作负责人（监护人）：` 之后取到下一个 `/` 为止 → `Person(name, "工作负责人")`，放在 `people` 第一个。
5. `fields["电话"]`：`电话：` 之后取到下一个 `/` 为止。`fields["单位班组"]`：`单位和班组：` 之后取到下一个 ` / `（两侧带空格的斜杠）为止，因为单位名里可能有 `/`。
6. `crew_size`：`总人数共\s*(\d+)\s*人`，找不到填 `None`。
7. `plan_start` / `plan_end`：分别对 `自` 之后、`至` 之后的文本调用 `parse_datetime`。日期各部分之间可能有任意空白。
8. `fields["分组派工单"]`：在含 `是否办理分组工作派工单` 的行里找 `[☑√]\s*(是|否)`，取“是”或“否”；两项都没勾填 `None`。
9. 工作班成员：含 `工作班人员（不包括工作负责人）：` 的行中该标签之后的文本，先去掉两端的空白和 `。.；;`，再按 `[、，,；;/\s]+` 拆分。每一段形如 `赵六（新员工）` 或 `赵六(新员工)` → `Person("赵六", "工作班成员", note="新员工")`，没有括号的 `note=None`。

**签名**
10. 对下表的每个标签，取第一个含该标签的行中标签之后的文本 `rest`：

| 标签 | role | 时间字段 |
|---|---|---|
| `工作票签发人签名：` | 签发人 | `fields["签发时间"]` |
| `工作票会签人签名：` | 会签人 | `fields["会签时间"]` |
| `工作票接收人签名：` | 接收人 | `fields["接收时间"]` |
| `工作许可人签名：` | 许可人 | `fields["许可时间"]` |

   - 人名：`rest` 开头（允许先有空白）匹配 `[^\s/（(：:]+`；后面如果紧跟（允许空白）`（张三代签）`、`(张三 代签)` 这类括号，就把括号里“代签”前的名字（去掉空白）记入 `signed_by`。人名位置是 `/` 时不产生 Person（表示没有这个人）。
   - 时间：`parse_datetime(rest)`，取 `rest` 里第一个时间（接收时间前面可能没写“时间：”）。
11. 专责监护人：在整张票面里匹配 `指定[\s/]*([^\s/]+?)[\s/]*为专责监护人`，命中就加 `Person(名字, "专责监护人")`；写的是 `/` 时匹配不到，不产生 Person。
12. `fields["安全交代时间"]`：以 `安全交代 |` 开头的行里的第一个时间。

`people` 的顺序：工作负责人、工作班成员（按票面顺序）、签发人、会签人、接收人、许可人、专责监护人。

**工作地点与停电范围**
13. `work_tasks`：以 `工作地点或设备（注明` 开头的行之后、含 `停电设备或线路名称：` 的行之前的每一行，取第 1、2 个单元格作为 `{"地点", "任务"}`（第 2 个没有就是空串）；两者都为空的行跳过。单元格内的 ` / ` 原样保留。
14. `outage_scope`：`停电设备或线路名称：` 之后的文本，去掉两端的空白、`/`、`。`、`.`。

**安全措施**
15. 从以 `调度或设备运维单位负责的安全措施` 开头的行起，到以 `工作班组自行装设的接地线` 开头的行之前，每行取第一个 `|` 之后的文本，在第一个全角冒号 `：` 处分成“栏目标签”和“内容”。按标签里的关键字定类别（按此顺序匹配，取第一个命中的）：

| 关键字 | category |
|---|---|
| 应拉 | 应拉开关刀闸熔断器 |
| 应投切 | 应投切电源及二次回路 |
| 接地 | 接地 |
| 标志牌 | 标志牌 |
| 保留或邻近 | 保留带电设备 |

16. 内容拆成条目：先按 ` / ` 拆；每段再在“`；` `;` `。` `！` `!` 之后紧跟编号”的位置拆开（编号指 `\d+[、.．]` 或 `（\d+）` / `(\d+)`）。每个条目去掉开头的编号和空白，再去掉两端的空白和 `；;。.`。空条目和恰好等于 `无` 的条目丢弃。`order` 是该条目在本类别中的序号，从 1 开始。
17. 班组自装接地：以 `工作班组自行装设的接地线` 开头的那一行，从第 3 个单元格起，每个单元格去掉其中的 ` / `（单元格内换行）和两端空白；不是空串、`无`、`/` 的，生成 `SafetyMeasure("班组自装接地", 文本, order=该单元格的序号，从 1 起)`。下一行的“编号”不解析。
18. `fields["备注"]`：票面中第一个以 `备注` 开头的行，取第一个 `：` 之后的文本，去掉两端的空白和 `/`。

## 不做

- 不解析工作间断、变更、延期、终结栏，不解析派工单，不解析“下达方式”。
- 不识别票种（调用方已经知道这是第一种票），不支持其他票种。
- 不做实体抽取（站名、线路、杆号是后面的任务），不改写措施文本。
- 不加日志、不加“宽松模式”参数、不对内部函数做类型检查。

## 验收

- `tests/test_t003_parser.py`（受保护）全部通过。它用 `tests/fixtures_d1.py` 的两张合成票逐字段核对，并在真实典票文本存在时跑集成检查（21 个场景都能解析，措施总数 187）。你不要去读真实文件；集成用例跑不过，就把失败信息写进 `questions`。

## 规模参考

参考实现约 100 行（含常量表），在 21 张真实典票上验证过。函数控制在 40 行以内：可以按“截取 / 表头 / 签名 / 工作地点与措施”拆成几个私有函数。预算 200 行是硬上限。
