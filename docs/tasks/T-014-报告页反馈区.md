## 目标

让试用的审票人能把“机器报得对不对”告诉开发者。

报告页写不回磁盘（ADR-0007 第 1 节），所以做成：在页面上每条事项下面选一下 → 页面最下面自动拼出一段文字 → 点“复制反馈”→ 贴到别处交给开发者。

**这段文字要能带出内网**，所以里面不能有票面内容：只有检查项的类别、标题、等级、审票人的选择，以及他自己写的补充说明。

## 接口（照写）

`report.rs` 新增两个常量：

```rust
pub const FEEDBACK_NOTE: &str = "反馈里只有每条事项的类别和你的选择，不带票面内容。补充说明里请不要写真实的人名、线路名、设备名和票号。";
pub const FEEDBACK_CHOICES: [&str; 4] = ["未评价", "属实", "误报", "说不清"];
```

其它公开接口不变。

## 规则（由规划者确定，不要改）

### 报告模型：末尾新增一个键 `feedback`

`build_report` 返回值在 `limits` 后面加 `"feedback"`，是反馈的抬头，三行：

```text
票审反馈（票审 {版本}，{模式}）
结论：{verdict.headline}
对照：{scenario.label}（相似度：{scenario.similarity}）
```

- `{版本}`：`env!("CARGO_PKG_VERSION")`。
- `{模式}`：`review.model` 是 `Off` → `规则模式`；`Done` → `模型模式`；`Failed` → `模型没有用上`（**不带原因**：原因里可能有文件路径）。
- `scenario.matched` 为假时，第三行是 `对照：没有找到对应的典票场景`。
- 行与行之间是 `\n`，末尾没有换行。

### 页面：每张事项卡片加一个下拉框

卡片最后（“这条规则还没有经过业务人员核对”那一段后面，`</div>` 前面）加：

```html
<p class="fb-line">这一条报得对不对（反馈用）：<select class="fb" data-item="{类别}｜{标题}｜{等级}" onchange="updateFeedback()"><option>未评价</option><option>属实</option><option>误报</option><option>说不清</option></select></p>
```

`{类别}`、`{标题}`、`{等级}` 是这条发现的 `group`、`title`、`label`，用全角竖线 `｜` 隔开，整体转义。选项来自 `FEEDBACK_CHOICES`。

`data-item` 里**只能**放这三样。`message`、`ticket_says`、`typical_text`、模型的看法都带着票面内容，不能放。

### 页面：新增一个区块，放在“对照的典票场景”后面、“机器的边界”前面

```html
<section id="feedback-section"><h2>给开发者的反馈</h2><p>试用时请顺手做三件事：在上面每条事项下选“属实 / 误报 / 说不清”；在这里选对照的场景对不对；把机器漏掉的问题写在补充说明里。然后点“复制反馈”，把文字交给开发者。</p><p class="secondary">{FEEDBACK_NOTE}</p><p>对照的典票场景对不对：<select class="fb-scene" data-item="对照的典票场景对不对：" onchange="updateFeedback()"><option>未评价</option><option>对</option><option>不对</option><option>说不清</option></select></p><p>补充说明（机器漏掉了什么、哪里看不懂）：</p><textarea id="note" class="short" aria-label="补充说明" onkeyup="updateFeedback()" onchange="updateFeedback()"></textarea><p>反馈内容：</p><textarea id="feedback" aria-label="反馈内容" readonly></textarea><button type="button" onclick="copyFeedback()">复制反馈</button></section>
```

### 脚本（ES5，和现有脚本放在同一个 `<script>` 里）

```js
function updateFeedback() {
    var items = document.querySelectorAll('select.fb');
    var lines = [{抬头}];
    for (var i = 0; i < items.length; i++) {
        lines.push((i + 1) + '. ' + items[i].getAttribute('data-item') + {竖线} + items[i].value);
    }
    var scene = document.querySelector('select.fb-scene');
    lines.push(scene.getAttribute('data-item') + scene.value);
    lines.push({补充} + document.getElementById('note').value);
    document.getElementById('feedback').value = lines.join('\n');
}
function copyFeedback() {
    updateFeedback();
    document.getElementById('feedback').select();
    document.execCommand('copy');
}
updateFeedback();
```

- `{抬头}` 是 `json_ascii(报告的 feedback)`，`{竖线}` 是 `json_ascii("｜")`，`{补充}` 是 `json_ascii("补充：")`——和现有的 `DRAFT_HEAD` 一样，中文以 `\uXXXX` 写进脚本。
- 脚本最后一句是 `updateFeedback();`：打开页面时就拼好一份（全是“未评价”）。

拼出来的反馈长这样：

```text
票审反馈（票审 0.2.0，模型模式）
结论：发现 1 处疑点，请逐条确认
对照：典票场景 16「……」（相似度：中）
1. 安全措施（对照典票）｜“接地”栏可能缺少一类措施｜疑点｜属实
2. 安全措施（对照典票）｜“应投切电源及二次回路”栏有一条措施的写法和典票不同｜提示｜未评价
对照的典票场景对不对：对
补充：
```

## 不做

- 不把反馈写到磁盘，不加“导出文件”按钮（浏览器里写不了本地文件，IE11 更不行）。
- 不把票面内容、文件名、模型的把握、规则编号放进反馈。
- 不给 `tg.exe` 加读取反馈的命令（以后有了真实反馈再说）。
- 不改现有七个区块的顺序和内容，不改 `main.rs`。
- 不用 ES5 以外的写法，不用 `<details>`、CSS 变量、grid（IE11）。
