## 目标

规则说“票面某一栏缺少一类措施”时，请本地小模型看一眼是不是只是写法不同。设计依据见 `docs/decisions/0008-模型模式与harness.md`，**先读它**。

这张卡只做核心库里的纯函数：读设置文件、拼提问、读模型的回答、解析 HTTP 应答、把模型的意见写回预审结果。**不启动进程，不连网络**——那是 T-013 的事，模型通过一个闭包 `ask` 传进来。

## 接口（照写）

### `schema.rs`

在 `Finding` 前面新增，并给 `Finding` 末尾加一个字段：

```rust
/// 模型对一条“疑似缺项”的复核意见（见 ADR-0008）。
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Second {
    /// 票面同一栏里，模型认为最接近的那条措施（原文）
    pub measure: String,
    /// 模型认为“是同一类措施”的把握，0～1
    pub p: f64,
    /// 把握达到阈值：模型认为只是写法不同
    pub same: bool,
}

pub struct Finding {
    // ……原有字段不动……
    pub unreviewed: bool,
    /// 模型的复核意见。规则模式下、或这一条不需要复核时是 None
    #[serde(default)]
    pub second: Option<Second>,
}
```

现有三处构造 `Finding` 的地方（`review.rs` 两处、`rules/engine.rs` 一处）都填 `second: None`。

### `review.rs`

```rust
/// 这次预审有没有请模型复核（见 ADR-0008）。

    Off,

    Failed(String),

pub struct Review {
    // ……原有字段不动……
    pub checked_rules: Vec<String>,
    pub model: ModelUse,

/// 按严重度排序。稳定排序：同一严重度内保持原顺序。
pub fn sort_findings(findings: &mut [Finding]);
```

- `ModelUse::Failed` 这张卡里没有地方构造它（T-013 用），照写即可。

### `harness.rs`（新文件，在 `lib.rs` 里加 `pub mod harness;`）

```rust
#[derive(Debug, Clone, Deserialize)]
pub struct Example {
    #[serde(rename = "典票")] pub typical: String,
    #[serde(rename = "票面")] pub ticket: String,
    #[serde(rename = "答案")] pub answer: String,
}

#[derive(Debug, Clone, Deserialize)]
pub struct Harness {
    pub version: String,
    pub server: String,
    pub model: String,
    pub model_bytes: u64,
    pub threads: u32,
    pub context: u32,
    pub threshold: f64,
    pub system: String,
    pub question: String,
    pub shots: Vec<Example>,
    pub selfcheck: Vec<Example>,
}

pub fn load_harness(path: &Path) -> Result<Harness, DataError>;
pub fn plain(text: &str) -> String;
pub fn request_body(harness: &Harness, typical: &str, measure: &str) -> String;
pub fn read_answer(response: &str) -> Result<f64, Error>;
pub fn http(stream: &mut (impl Read + Write), method: &str, path: &str, body: &str) -> Result<(u16, String), Error>;
pub fn selfcheck(harness: &Harness, ask: &mut impl FnMut(&str) -> Result<String, Error>) -> Result<(), Error>;
pub fn second_opinion(
    review: &mut Review,
    templates: &[Template],
    harness: &Harness,
    ask: &mut impl FnMut(&str) -> Result<String, Error>,
) -> Result<(), Error>;
```

`Error` 是 `crate::Error`，`DataError` 是 `crate::entities::DataError`。`ask` 收到一次提问的请求正文，返回模型程序的应答正文。

## 规则（由规划者确定，不要改）

### `load_harness`

读 JSON 并反序列化成 `Harness`（文件里多出来的“说明”字段忽略）。报错一律是 `{路径}：{原因}`：

| 情况 | 原因 |
|---|---|
| 读不了文件 | `读取失败（{err}）` |
| 不是合法 JSON、缺字段、类型不对 | `设置不合规范（{err}）`（serde 的报错里带着字段名，够用） |
| `threshold` 不在 (0.5, 1] | `threshold 要大于 0.5、不超过 1` |
| `question` 里没有同时出现 `{典票}` 和 `{票面}` | `question 里要同时有 {典票} 和 {票面}` |
| `shots` 或 `selfcheck` 里有“答案”不是 `是` / `否` | `shots 和 selfcheck 的“答案”只能是“是”或“否”` |
| `selfcheck` 里没有答案为“是”的题，或没有答案为“否”的题 | `selfcheck 里至少要有一道答案为“{是或否}”的题` |

### `plain`

`abstract_text(text)` 之后把 `{站}` → `某站`、`{线路}` → `某线`、`{杆号}` → `某号杆`、`{编号}` → 空串。

### `request_body`

返回 JSON 字符串，键的顺序照写：

```text
messages               见下
max_tokens             1
temperature            0
logprobs               true
top_logprobs           20
chat_template_kwargs   {"enable_thinking": false}
cache_prompt           true
```

`messages`：先一条 `{"role": "system", "content": harness.system}`；然后每道例题两条——`user`（题面）和 `assistant`（例题的答案）；最后一条 `user` 是本题的题面。

题面 = `harness.question` 里的 `{典票}` 换成 `plain(典票措施)`、`{票面}` 换成 `plain(票面措施)`。**例题和本题都要过 `plain`。**

这个写法是 ADR-0008 实测时用的，阈值是在它上面定的，一个字都不能变。

### `read_answer`

应答是 OpenAI 兼容格式。取 `choices[0].logprobs.content[0].top_logprobs`（数组，每项有 `token` 和 `logprob`）。`token` 等于 `是` 的那项概率 `exp(logprob)` 记作 yes，`否` 的记作 no，数组里没有的算 0。

- 不是合法 JSON → `模型的应答不是合法 JSON（{err}）`
- 取不到那个数组 → `模型的应答里没有各个字的概率（top_logprobs）`
- `yes + no < 0.5` → `模型没有回答“是”或“否”`
- 否则返回 `yes / (yes + no)`

### `http`

在一条已经连上的流上发一个请求、读一个应答。请求逐字是：

```text
{method} {path} HTTP/1.1\r\n
Host: 127.0.0.1\r\n
Content-Type: application/json\r\n
Content-Length: {body 的字节数}\r\n
Connection: close\r\n
\r\n
{body}
```

然后一直读到对方关闭（`read_to_end`），按第一个 `\r\n\r\n` 分成头和正文，返回（状态码，正文）。状态码不是 200 也照实返回，由调用方处理。

失败一律是 `和模型程序通信失败（{原因}）`：读写出错（原因用 io 错误的文字）、应答不是 UTF-8（`应答不是 UTF-8`）、找不到 `\r\n\r\n`（`应答不完整`）、头里有 `transfer-encoding`（不分大小写；`不支持分块应答`）、状态行取不出数字（`状态行不对`）。

### `selfcheck`

按顺序把 `harness.selfcheck` 的每道题问一遍（`request_body` → `ask` → `read_answer`）。`p >= threshold` 算模型答“是”。和题目的答案不一致，立刻返回：

`模型自检没有通过：第 {n} 道自检题应当回答“{答案}”。模型文件或设置可能不对`（n 从 1 起）

`ask` 或 `read_answer` 出错，原样往上传。

### `second_opinion`

对 `review.findings` 里每条 `rule_id == "CMP-MISSING"` 的发现，按发现的顺序：

1. 找到它对应的模板必备措施：模板是 `scenario_id` 那个，措施是 `evidence`（措施编号）那条。它的 `category` 就是要看的那一栏。找不到属于内部不变量被破坏，用 `expect`。
2. 票面上 `category` 相同的每条措施（按票面顺序），各问一次：`request_body(harness, &finding.typical_text, &measure.text)`。
3. 取把握最大的那条（并列取先问的），记成 `Second { measure: 那条措施的原文, p, same: p >= harness.threshold }`。这一栏一条措施都没有：不问，`second` 留 `None`。

全部问完之后才动 `review`（中途任何一次出错：原样返回错误，`review` 一个字都不改）：

- 每条问过的发现写上 `second`。
- `same` 为真的那些，另外改四处，其余字段不动：
  - `rule_id` = `CMP-REWORDED`
  - `severity` = `Severity::Info`
  - `title` = `“{类别}”栏有一条措施的写法和典票不同`
  - `message` = `对照典票场景 {n}「{模板标题}」，票面“{类别}”栏里没有找到字面一致的这类措施；模型认为票面上有一条和它是同一类措施，只是写法不同，请确认。`（`{n}` 是 `scenario_number`）
- `sort_findings`。
- `review.model = ModelUse::Done { asked }`，`asked` 是提问的总次数（没有可问的也是 `Done { asked: 0 }`）。

## 不做

- 不启动进程、不连网络、不出现 `std::net`（门禁会拦）。`http` 只认 `Read + Write`。
- 不改 `report.rs`，不改命令行（报告页怎么显示模型的意见是 T-013）。
- 不做重试、超时、缓存、并发；不给 `Harness` 加默认值；不新建 trait。
- 模型出错时不“退回规则结果继续”——这里只管把错误传上去，怎么处置由调用方决定。
- 不把阈值、提示词写死在代码里，都从 `Harness` 读。
