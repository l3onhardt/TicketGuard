## 目标

把典票库里每个第一种票场景转成一个模板 JSON（`data/templates/D1/D1-Sxx.json`），供后面的场景匹配和措施比对使用。模板的核心是 `required_measures`：从典票的安全措施里提炼出“这类作业必须有哪些措施”，用关键词签名表示，和具体线路、编号无关。生成后由业务人员人工修订（所以 `status` 固定为 `draft`）。

## 接口（照写）

```python
# src/ticketguard/templates.py
def required_measures(ticket: Ticket, lexicon: dict, prefix: str) -> list[dict]: ...
def build_template(chunk: ScenarioChunk, ticket: Ticket, lexicon: dict) -> dict: ...
def load_templates(directory: str | Path) -> list[dict]: ...
```

命令行（加在 `__main__.py`，照现有 `ingest` 子命令的写法）：

```
python -m ticketguard templates <典票文本.txt> [输出目录，默认 data/templates/D1] [--lexicon 词表，默认 data/rules/lexicon.json]
```

读文本 → `split_scenarios` → 只取 `section == "配电第一种工作票典型场景"` 的场景 → `parse_dist1(chunk.text)` → `build_template` → 每个场景写一个 `<id>.json`（UTF-8，`ensure_ascii=False`，`indent=2`）→ 打印 `已生成 N 个模板 → <输出目录>`。输出目录不存在就创建。

## 规则（由规划者确定，不要改）

**`required_measures`**：按 `ticket.measures` 的顺序逐条处理，维护一个签名列表，每项是（category, keywords, 原文）：
1. `kw = keywords(措施原文, lexicon)`；`kw` 为空的措施跳过。
2. 如果列表里已有同 category、且关键词集合 ⊇ `set(kw)` 的项，跳过这条（已被包含）。
3. 否则，先删除列表里同 category、且关键词集合是 `set(kw)` 真子集的项，再把这条追加到列表末尾。
4. 最后按列表顺序输出，`id` 为 `f"{prefix}-M{序号:02d}"`（从 1 起），字段依次为 `id`、`category`、`pattern`（`abstract(原文)`）、`keywords`（即 `kw`，保持词表顺序）、`must`。
5. `must`：原文匹配正则 `则无需|则不用|无需填写|不用写` 时为 `False`（例如“（无合闸压板，则无需填写此项）”“（若线路未投自愈，则不用写）”），否则为 `True`。

**`build_template`** 返回的 dict，键依次为：
- `id`：`f"D1-S{int(chunk.number):02d}"`；
- `ticket_type`：`ticket.ticket_type.value`；
- `title`：`chunk.title` 去掉结尾的 `（有调整）` 或 `（新增）`（全角或半角括号都算），再去两端空白；
- `source`：`{"doc": "2026.9典票库", "section": chunk.section, "scenario": chunk.number, "status": "有调整" / "新增" / ""}`；
- `work_task`：`abstract(工作任务原文)`。工作任务原文这样取：在 `chunk.text` 中，从第一行起逐行查找，直到遇到“去掉行首空白后以 `编号：` 开头”的行为止；第一个含 `工作任务：` 的行，取 `工作任务：` 之后的文本（去掉两端空白）；如果为空，就取下一行（去掉两端空白）。一直没找到，就用 `ticket.work_tasks[0]["任务"]`（没有 work_tasks 时用空串）；
- `required_measures`：`required_measures(ticket, lexicon, id)`；
- `status`：`"draft"`。

**`load_templates`**：读目录下所有 `*.json`（按文件名排序），每个文件是一个模板。缺少 `id`、`ticket_type`、`title`、`work_task`、`required_measures` 中任一字段时抛 `ValueError`，消息写出文件路径和缺的字段。

## 不做

- 不生成 `example_ticket`（不把典票全文放进仓库），不抽取风险点。
- 不处理第一种票以外的票种。
- `templates` 子命令不覆盖保护、不比对旧文件：直接覆盖写。
- 不在 `load_templates` 里校验 `required_measures` 内部字段（以后需要再说）。

## 验收

- `tests/test_t005_templates.py`（受保护）全部通过。生成真实模板由规划者执行，你不要读 `data/interim`。
