## 目标

审票人拿到一张票（票面文本 `.txt`，或 `.docx`），运行一条命令，得到：命令行摘要、一份 JSON、一份**能直接双击打开**的 HTML 报告。HTML 里可以勾选问题，自动拼出“打回意见草稿”供复制。**是否打回由人决定**，报告用语只能是“预审 / 疑似 / 建议 / 需人工确认”。

## 接口（照写）

```python
# src/ticketguard/report.py
TITLE: str = "工作票智能预审报告"
DISCLAIMER: str = "本报告是智能预审结果，所列均为“疑似问题”和建议，需审票人逐条人工确认；是否接收或打回，由审票人决定。"
LIMITS: list[str] = [
    "不判断现场物理条件（如实际安全距离、所拉开关能否真正隔离作业区），这些需要结合配网拓扑和现场勘察。",
    "本次只使用规则基线（字面和同义词比对），未启用语义判断：措施换了说法、或规则没有覆盖到的问题，可能漏报或误报。",
    "目前规则库仍是草稿，尚未经业务人员逐条核对，规则类发现一律只作为“提示”。",
]
LABELS: dict[Severity, str] = {Severity.ERROR: "疑似违反条款", Severity.WARNING: "疑似问题", Severity.INFO: "提示"}
DRAFT_HEAD: str = "预审意见（草稿，请核实后使用）："

def draft_text(findings: list[Finding]) -> str: ...
def build_report(review: Review, templates: list[dict], source: str) -> dict: ...
def render_html(report: dict) -> str: ...
```

命令行（加到 `__main__.py`）：

```
python -m ticketguard check <票面文件> [--out 默认 reports] [--templates 默认 data/templates/D1]
       [--rules 默认 data/rules] [--lexicon 默认 data/rules/lexicon.json]
```

## 规则（由规划者确定，不要改）

**`draft_text`**：取 `severity != INFO` 的发现，每条写成 `<序号>. <message>（依据：<basis.doc> <basis.clause>）`，序号从 1 起；第一行是 `DRAFT_HEAD`，行间用 `\n`。一条都没有时返回空字符串。

**`build_report`** 返回（键的顺序照写）：

```python
{"title": TITLE, "source": source, "disclaimer": DISCLAIMER, "limits": LIMITS,
 "ticket": {"number", "type"（ticket_type.value）, "plan_start", "plan_end", "work_tasks"},
 "candidates": [{"id", "title"（模板的 title）, "score"（round 到 4 位）}],   # 顺序同 review.candidates
 "findings": [asdict(f) 再把 severity 换成字符串值，并加上 "label": LABELS[f.severity]],
 "draft": draft_text(review.findings)}
```

**`render_html(report)`** 输出一个完整的 HTML 页面（`<!doctype html>`，`<meta charset="utf-8">`）：

1. **完全离线**：CSS 和 JS 全部内联；不得出现 `http://`、`https://`、`<link`、`src=`。
2. **所有来自票面、规则、模板的文字都用 `html.escape` 转义**（包括写进属性的）。
3. 依次包含：标题；`DISCLAIMER`；票面概况（编号、票种、计划工作时间、每条工作任务的“地点：任务”）；候选场景表（id、名称、匹配度保留两位小数）；疑似问题表；打回意见草稿；局限说明（`LIMITS` 每条一个 `<li>`）。
4. 疑似问题表每条发现一行：一个 `<input type="checkbox" class="pick" ...>`，`severity` 不是 `info` 的默认 `checked`；`data-text` 属性的值为 `<message>（依据：<doc> <clause>）`（转义后）；然后是 `label`、`message`，以及依据的 `doc`、`clause`、`text`，`source` 不为空时再加上 `（出处：<source>）`。
5. 草稿：`<textarea id="draft">` 里放转义后的 `report["draft"]`；勾选框的 `onchange` 调用一个内联 JS 函数，按当前勾选的顺序把 `data-text` 重新拼成和 `draft_text` 同样格式的文字写回 textarea（`DRAFT_HEAD` 用 `json.dumps` 写进 JS）。再给一个“复制草稿”按钮（`select()` 后 `document.execCommand('copy')`）。JS 不得用模板字符串（反引号）。

**`check` 命令**：
1. 后缀（不区分大小写）是 `.docx` 就用 `blocks_to_text(read_docx(p))`；是 `.txt` 就按 UTF-8 读；其他后缀抛 `ValueError`，消息里含 `只支持 .txt（票面文本）和 .docx`。
2. `review_text` → `build_report(review, templates, 文件名 p.name)`。
3. 写 `<out>/<p.stem>.预审.json`（`ensure_ascii=False`，`indent=2`）和 `<out>/<p.stem>.预审.html`，目录不存在就创建。文件名用字符串拼接，**不要用 `with_suffix`**。
4. 打印：
```
工作票 <编号>：最接近典票场景 <id>「<title>」（匹配度 0.xx）
疑似问题 N 条（需人工确认）：
  [<label>] <message>          ← 每条一行
报告 → <html 路径>
```

**`required_field` 算子的参数改为字典**（`data/rules/ticket.rules.json` 已由规划者改好）：`params["fields"]` 是 `{路径: 中文栏目名}`，按字典顺序逐个检查，违规项的 `field` 填**中文栏目名**。原因：提示文字是给审票人看的，不能出现 `plan_end` 这样的内部字段名。

## 不做

- 不做 PDF 输入（ADR-0003 等内网实测）。
- 不做批量审查、不做 GUI、不做报告历史和对比。
- 不在报告里写“违章”“不合格”“必须打回”这类定性用语。
