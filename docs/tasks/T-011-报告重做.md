## 目标

把预审报告重做成审票人一眼能看懂的页面。设计依据见 `docs/decisions/0007-前端形态与报告版式.md`，**先读它**。

用的人是工作票接收人、许可人，不是技术人员。页面要回答他的四个问题：这是哪张票 → 机器查出了什么 → 机器到底查了哪些、哪些没查 → 具体问题和依据是什么、打回的话怎么写。

页面上不得出现任何内部标识（规则编号、措施编号、`D1-S01`、匹配度数字、`{线路}` 这类占位符）。这些只留在报告 JSON 里。

## 接口（照写）

### `schema.rs`：`Finding` 末尾新增 4 个字段

```rust
pub struct Finding {
    // ……原有字段不动……
    pub scenario_id: Option<String>,
    /// 给人看的短标题
    pub title: String,
    /// 票面上对应位置写的内容。没有就是空串
    pub ticket_says: String,
    /// 典票上的原文（只有措施比对的发现才有）。没有就是空串
    pub typical_text: String,
    /// 产生它的规则还是草稿，没有经过业务人员核对
    pub unreviewed: bool,
}
```

### `rules/engine.rs`

- `Rule` 新增 `pub title: String`（取规则 JSON 的 `title`）。
- `run_rules` 产生的 `Finding`：`title` = 规则的 `title`；`ticket_says` = 违规项里的 `evidence`（没有就是空串）；`typical_text` 为空串；`unreviewed` = 规则的 `status == "draft"`。其它字段的取值不变。

- `compare_measures` 产生的 `CMP-MISSING` 发现改成（`{n}` 是 `scenario_number`，其余字段不变，`evidence` 仍是措施编号）：
  - `title`：`“{类别}”栏可能缺少一类措施`
  - `message`：`对照典票场景 {n}「{模板标题}」，票面“{类别}”栏中没有找到这类措施。`
  - `typical_text`：模板必备措施的 `source_text`
  - `ticket_says`：票面上同一类别的全部措施原文，用 `；` 连起来；这一类别一条措施都没有时，写 `这一栏没有填写措施（写的是“无”或空着）`

- `MATCH-LOW` 发现改成：`title` = `没有找到对应的典票场景`；`message` = `没有找到足够相似的典票场景，本次没有做安全措施比对，请人工审核全部安全措施。`；其余新字段为空串 / `false`。

## 规则（由规划者确定，不要改）

### 报告模型：`build_report` 的返回值

键的顺序照写：

```text
title        TITLE
source       传入的文件名
disclaimer   DISCLAIMER
ticket       {number, type, plan_start, plan_end, leader, crew_size, work_tasks: [{地点, 任务}]}
verdict      {level, headline, detail}
checklist    [{name, status, detail}]
findings     [见下]
scenario     {matched, label, similarity, score, caution, others: [{label, similarity, score}]}
draft        draft_text(&review.findings)
limits       LIMITS
```

- `ticket.leader`：角色为“工作负责人”的人名，没有就是 `null`。`number`、`plan_start`、`plan_end`、`crew_size` 没有时也是 `null`。

**`findings`**，顺序同 `review.findings`，每条的键顺序：

```text
rule_id, severity, label, group, title, message, ticket_says, typical_text,
basis: {doc, clause, text, source}, unreviewed, picked, draft_line,
evidence, confidence, scenario_id
```

- `label`：`label(severity)`。
- `picked`：`severity` 不是 `info`。
- `draft_line`：`{message}（依据：{basis.doc} {basis.clause}）`。
- `group`：按规则编号的前缀分组——

  | 前缀 | 组名 |
  |---|---|
  | `R-REQ-` | 票面必填与签名 |
  | `R-CREW-`、`R-NEW-` | 人员与人数 |
  | `R-TIME-` | 时间顺序 |
  | `R-LOC-` | 工作地点 |
  | `R-HOT-`、`R-LIVE-` | 特殊作业要求 |
  | `CMP-MISSING`、`MATCH-LOW` | 安全措施（对照典票） |
  | 其它 | 其他检查 |

**`draft_text`**：取 `severity` 不是 `info` 的发现，每条一行 `<序号>. <draft_line>`，序号在**被选中的发现里**从 1 连续编号；第一行是 `DRAFT_HEAD`，行间用 `\n`。一条都没有时返回空字符串。

**`verdict`**，按下表从上到下取第一个满足的：

| level | 条件 | headline | detail |
|---|---|---|---|
| `issues` | 有 `severity` 不是 `info` 的发现，共 N 条 | `发现 N 处疑点，请逐条确认` | `确认属实的事项，勾选后会写进下方的打回意见草稿。` |
| `no_scenario` | 有 `MATCH-LOW` 发现 | `没有找到对应的典票场景，安全措施没有做比对` | `这张票的安全措施需要完全由人工审核。其余项目的检查结果见下方清单。` |
| `notes` | 有 `info` 发现，共 N 条 | `机器没有发现疑点，有 N 条提示请过目` | `提示不一定是问题。机器只查了下方清单里的项目，其余请人工审核。` |
| `clear` | 没有任何发现 | `机器检查的项目没有发现疑点` | `机器只查了下方清单里的项目，其余请人工审核。` |

**`checklist`**，按这个顺序出行：

1. 上表前五个规则组（再加“其他检查”），**只列出 `review.checked_rules` 里至少有一条规则属于它的组**：
   - 组里有发现（N 条）：`status = "found"`，`detail = 有 N 条需要确认，见下方`
   - 没有发现：`status = "checked"`，`detail = 检查了 K 项，没有发现疑点`（K 是 `checked_rules` 里属于这个组的规则数）
2. `安全措施（对照典票）`，一定有这一行（`{场景}` 是 `scenario.label`）：
   - 有 `MATCH-LOW`：`status = "skipped"`，`detail = 没有找到足够相似的典票场景，没有做比对。请人工审核全部安全措施`
   - 有 `CMP-MISSING`（N 条）：`status = "found"`，`detail = 对照{场景}，有 N 类措施没有找到，见下方`
   - 都没有：`status = "checked"`，`detail = 对照{场景}，各类必备措施都找到了`
3. `机器查不了的项目`，一定有这一行：`status = "skipped"`，`detail = MANUAL_ITEMS`

**`scenario`**（`review.candidates` 是按分数排好的前 3 名）：

- `label`：`典票场景 {n}「{模板标题}」`，取第 1 名。
- `score`：第 1 名的分数，四舍五入到 4 位小数。
- `similarity`：分数 ≥ 0.60 是 `高`，≥ 0.45 是 `中`，否则 `低`。
- `matched`：没有 `MATCH-LOW` 发现时为 `true`。
- `caution`：`matched` 且 `similarity` 是 `低` 时为 `相似度低，对照的场景可能不对，措施比对的结果仅供参考。`，否则是空串。
- `others`：第 2、3 名，各有 `label`、`similarity`、`score`，算法同上。

### 页面：`render_html`

输出一个完整的 HTML 页面（`<!doctype html>`、`<html lang="zh-CN">`、`<meta charset="utf-8">`、`<title>` 是 `TITLE`）。从上到下七个区块，每个区块的最外层元素带固定的 `id`：

| # | `id` | 内容 |
|---|---|---|
| ① | `ticket` | 小标题 `TITLE`；票号（最醒目）、票种；计划工作时间（起 至 止）、工作负责人、总人数；每条工作任务一行“地点：任务”。空值写 `未填写` |
| ② | `verdict` | `<div id="verdict" class="verdict verdict-{level}" data-level="{level}">`，里面 `headline` 一行（大字）、`detail` 一行 |
| ③ | `checklist` | 标题 `机器查了什么`。一张三列的表：状态、检查项、说明。每行 `<tr class="check-{status}">`。状态列的文字：`checked` → `✓ 已查，无疑点`；`found` → `! 需要确认`；`skipped` → `— 机器没查` |
| ④ | `findings` | 标题 `需要确认的事项`。每条发现一张卡片（见下）。一条都没有时写一句 `没有需要确认的事项。` |
| ⑤ | `draft-section` | 标题 `打回意见草稿`；一句说明 `草稿由上面勾选的事项拼成，可以直接修改。是否打回由你决定。`；`<textarea id="draft">`；按钮 `复制草稿`、`打印报告` |
| ⑥ | `scenario` | 标题 `对照的典票场景`。`matched` 时：`本票对照的是 {label}（相似度：{similarity}）。`；不 `matched` 时：`没有找到足够相似的典票场景。最接近的是 {label}（相似度：{similarity}）。`。`caution` 不为空就另起一行写出来。`others` 不为空时列出 `其他相近的场景：` 和各自的“label（相似度：x）”，并加一句 `如果你认为这张票属于别的场景，上面“安全措施”一项的比对结果不适用。` |
| ⑦ | `limits` | 标题 `机器的边界`。`DISCLAIMER` 一段；`LIMITS` 每条一个 `<li>`；最后一行 `报告对应的文件：{source}` |

**发现卡片**：`<div class="finding finding-{severity}">`，里面依次是：

1. 勾选框：`<input type="checkbox" class="pick" data-text="{转义后的 draft_line}" onchange="updateDraft()"{ checked}>`，`picked` 为真时带 ` checked`。属性的顺序和写法照这个来（验收测试按它数）。勾选框旁边的文字是 `写进打回意见`。
2. `label`（疑点 / 提示）和 `group`，作为两个小标签。
3. `title`，卡片里最醒目的一行。
4. `message`。
5. `ticket_says` 不为空时：`票面上：{ticket_says}`。（“票面上：”和下一条的“典票上的写法：”这两个字样，页面其它地方不要再用——验收测试按出现次数核对。）
6. `typical_text` 不为空时：`典票上的写法：{typical_text}`，后面跟一句小字 `（这是典票里同类作业的写法，线路和设备名称会和本票不同）`。
7. 依据：`依据：{doc} {clause}：{text}`，`source` 不为空时加 `（出处：{source}）`。字号比正文小、颜色浅。
8. `unreviewed` 为真时：`这条规则还没有经过业务人员核对，暂时只作为提示。`

**脚本**（内联，只用 ES5）：

- `updateDraft()`：按页面上的顺序，把勾选了的 `input.pick` 的 `data-text` 拼成和 `draft_text` 同样格式的文字写回 `#draft`；一条都没勾就清空。`DRAFT_HEAD` 用 `json_ascii` 写进脚本（保留现有的 `json_ascii` 函数）。
- `copyDraft()`：选中 `#draft` 的内容并 `document.execCommand('copy')`。
- “打印报告”按钮调用 `window.print()`。

**硬性约束**（验收测试逐条检查）：

- 页面里不得出现：规则编号（`R-CREW`、`R-REQ`、`R-TIME`、`R-LOC`、`R-NEW`、`R-HOT`、`R-LIVE`）、`CMP-MISSING`、`MATCH-LOW`、`D1-S`、`{线路}` `{杆号}` `{编号}` `{站}`、`匹配度`，以及这几个 JSON 键名：`rule_id`、`scenario_id`、`draft_line`、`confidence`（所以 CSS 类名、`data-` 属性也不要用这些字样，不要把编号写进属性）。
- 页面里不得出现这些说法：`违章`、`不合格`、`必须打回`、`审核通过`、`没有问题`、`无问题`。
- 完全离线：不得出现 `http://`、`https://`、`<link`、`src=`。
- 为了 IE11：脚本里不得出现反引号、`=>`、`let `、`const `、`.forEach(`；样式里不得出现 `var(--`、`display: grid`、`display:grid`；页面里不得出现 `<details`。
- 所有来自票面、规则、模板的文字都要转义（沿用现有的 `escape` 函数），包括写进属性里的。

### 版式与视觉（照做）

- 单列，内容区最大宽度 60rem，居中；页面底色 `#f5f7fa`，区块是白底、`1px solid #d9e2ec` 的边框、适当的内边距，区块之间留白。
- 字体 `"Microsoft YaHei", "PingFang SC", sans-serif`，正文 16px，行高 1.7，正文颜色 `#1f2933`，次要文字 `#52606d`。
- 结论条是全页最显眼的元素：左侧 6px 的粗边加浅底色，`headline` 约 1.5rem、加粗。四种状态的配色（边 / 底）：`issues` `#b45309` / `#fff7ed`；`no_scenario` `#52606d` / `#f0f4f8`；`notes` `#1d4ed8` / `#eff6ff`；`clear` `#15803d` / `#f0fdf4`。
- 审票清单：状态列固定宽度、不换行；三种状态的文字颜色分别是 `#15803d`（checked）、`#b45309`（found）、`#52606d`（skipped）。**状态不能只靠颜色区分**——前面的符号和文字必须有。
- 发现卡片：左侧 4px 粗边，疑点 `#b45309`，提示 `#1d4ed8`；`title` 加粗、比正文大一号；小标签是带边框的小字。
- 按钮和勾选框要够大、好点（按钮内边距不小于 `.5rem 1rem`）。
- 打印（`@media print`）：隐藏按钮；页面底色改白；卡片不要被分页切开（`page-break-inside: avoid`）。
- 窄屏（宽度 ≤ 640px）时内边距收小，不出现横向滚动条（清单表格里的长文字要能换行）。
