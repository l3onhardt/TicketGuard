## 目标

把前面的部件串成一张票的完整审查：解析票面 → 跑规则 → 找最像的典票场景 → 对照该场景的必备措施，找出票面上缺的。设计依据见 `docs/decisions/0004-措施比对用关键词签名.md`，先读它。

## 接口（照写）

```python
# src/ticketguard/review.py
MATCH_MIN = 0.4
CMP_BASIS: Basis   # 见下方规则 4

@dataclass
class Review:
    ticket: Ticket
    candidates: list[tuple[str, float]]   # 最多 3 个 (模板 id, 匹配分)，分数从高到低
    findings: list[Finding]

def match_scenario(ticket: Ticket, templates: list[dict], lexicon: dict) -> list[tuple[str, float]]: ...
def compare_measures(ticket: Ticket, template: dict, lexicon: dict, confidence: float) -> list[Finding]: ...
def review_text(text: str, rules: list[dict], templates: list[dict], lexicon: dict) -> Review: ...
```

## 规则（由规划者确定，不要改）

1. **`match_scenario`**：对每个模板算一个分数，返回全部 `(id, 分数)`，按分数从高到低排，同分按 id 升序。
   - 清洗函数 `clean(s)`：`normalize(abstract(s), lexicon)` 之后，删除所有 `{…}` 占位符。
   - 票面文字 = `clean` 所有 work_task 的 `地点 + 任务` 拼接（无分隔符）；模板文字 = `clean(title + work_task)`。
   - 二元字集合：字符串中所有相邻两个字符组成的集合。
   - 票面签名 = 所有措施的 `(category, 关键词)` 集合（关键词用 `entities.keywords`）；模板签名 = 所有必备措施的 `(category, 关键词)` 集合。
   - Jaccard(a, b) = |a∩b| / |a∪b|，两个都为空时为 0。
   - 分数 = 0.5 × Jaccard(两段文字的二元字集合) + 0.5 × Jaccard(两个签名)。
2. **`compare_measures`**：对模板的每条必备措施 `rm`：票面上只要有一条措施满足 `category == rm["category"]` 且 `set(rm["keywords"]) ⊆ set(keywords(措施原文))`，就算有；否则生成：
   - `Finding(rule_id="CMP-MISSING", severity=WARNING（rm["must"] 为真）或 INFO（为假）, message=见下, basis=CMP_BASIS, evidence=rm["id"], confidence=confidence, needs_review=True, scenario_id=template["id"])`
   - message：`f"对照典票场景 {template['id']}「{template['title']}」（匹配度 {confidence:.2f}），票面“{rm['category']}”栏中没有找到这类措施：{rm['pattern']}"`
3. **`review_text`**：
   - `ticket = parse_dist1(text)`；`findings = run_rules(ticket, rules)`；`candidates = match_scenario(...)`。
   - 最高分 ≥ `MATCH_MIN`：对最高分的模板做 `compare_measures`（confidence 用最高分），结果追加到 findings。
   - 否则追加一条 `Finding("MATCH-LOW", INFO, f"没有找到足够相似的典票场景（最接近的是 {id}，匹配度 {分数:.2f}），本次未做安全措施比对。", CMP_BASIS, confidence=最高分, needs_review=True)`。
   - findings 按严重度排序（error → warning → info），同一严重度内保持原有顺序（稳定排序）。
   - 返回 `Review(ticket, candidates[:3], findings)`。
4. `CMP_BASIS = Basis(doc="《中国南方电网有限责任公司电力安全工作规程第3部分：配电》（典票库第一章转述）", clause="5.3.1", text="工作票所列安全措施正确、完备，由工作负责人、签发人、会签人、工作票接收人、许可人负责。", source="2026.9典票库 第一章“两票”相关文件内容说明")`。

## 不做

- 不实现 `DecisionBackend` 的子类，不调用模型（见 ADR-0004 第 6 条）。
- 不读文件：规则、模板、词表都由调用方传入。
- 不做票种识别，只支持配电第一种工作票。
- 不对措施做“多了”的检查（票面比模板多出的措施不报）。
