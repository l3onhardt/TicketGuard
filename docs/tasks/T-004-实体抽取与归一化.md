## 目标

给后面的规则（工作地点核对）和措施比对提供几个纯函数：从票面文字里抽出线路、变电站、杆号，把措施文字归一化、占位符化，并按词表生成“关键词签名”。词表 `data/rules/lexicon.json` 已由规划者写好，业务人员以后会直接编辑它。

## 接口（照写）

```python
# src/ticketguard/entities.py
def load_lexicon(path: str | Path) -> dict: ...         # 读词表 JSON
def normalize(text: str, lexicon: dict) -> str: ...      # 归一化
def lines(text: str) -> set[str]: ...                    # 线路，如 {"10kV测试线"}
def stations(text: str) -> set[str]: ...                 # 变电站，如 {"35kV甲站"}
def poles(text: str) -> list[str]: ...                   # 杆号，按出现顺序，如 ["5", "7", "1+1"]
def abstract(text: str) -> str: ...                      # 占位符化
def keywords(text: str, lexicon: dict) -> list[str]: ... # 关键词签名
```

## 规则（由规划者确定，不要改）

正则里的“名字字符”指：不是空白、不是 `，,、；;。:：/`、不是字母 `k` `V`、不是中文引号 `“”` 的任意字符。

1. `load_lexicon`：用 UTF-8 读 JSON；缺少 `synonyms` 或 `keywords` 字段时抛 `ValueError`，消息里写出文件路径和缺的字段名。
2. `normalize`：
   - 删除所有空白（包括全角空格）；把 `！` 换成 `!`，把 `，` 换成 `,`；
   - 然后按 `synonyms`（键是规范写法，值是它的其他写法列表）把其他写法替换成规范写法。所有“其他写法”**按长度从长到短**依次替换，避免短词先替换破坏长词。
3. 抽取前先删除括号内容：`（…）` 和 `(…)`（不嵌套，最内层），用于 `lines` 和 `stations`。例如“10kV测试线（与10kV示范线同塔架设）”中的示范线不算。
4. `stations`：匹配 `(?<![\d.])\d+kV` + 一个或多个名字字符（非贪婪）+ `站`，返回整段（如 `35kV甲站`）。
5. `lines`：匹配 `(?<![\d.])(\d+(?:\.\d+)?kV)` + 一个或多个名字字符（非贪婪）+ `线`，得到电压和名称两部分。名称满足以下任一条件时**不是线路**，丢弃：
   - 以 `进线` `出线` `引线` `引流线` `接线` `母线` `导线` `地线` `跳线` 结尾；
   - 含 `开闭所` `公变` `专变` `开关` `刀闸` `站`。
   名称里“非数字字符后紧跟 3 位数字再接 `线`”的调度编号要去掉：`示范916线` → `示范线`。返回“电压+名称”，如 `10kV示范线`、`0.4kVII线`。
6. `poles`：依次找 `(\d+(?:\+\d+)?)号(杆|塔)` 或 `#(\d+(?:\+\d+)?)` 后面可选一个 `杆`，返回数字部分，按出现顺序（不去重）。
7. `abstract`：按顺序做三次替换：
   - 规则 4 的变电站 → `{站}`；
   - 规则 5 的线路（只替换“是线路”的匹配，整段含电压一起替换）→ `{线路}`；
   - 规则 6 的杆号（整段，包括“号杆”或 `#`）→ `{杆号}`；
   - 紧跟在 `接地刀闸` `开关` `刀闸` `令克` 前面的连续数字 → `{编号}`。
   注意：`abstract` **不**删除括号内容，不做归一化。
8. `keywords`：先 `normalize(text)`；对词表 `keywords` 里的每个词也做 `normalize`，凡是出现在文本中的，按词表顺序返回原词（不是归一化后的词）。

## 不做

- 不抽取分支线名、设备双重名称、大号侧和小号侧（以后需要再开卡）。
- 不缓存词表，不提供默认词表路径，不做编码探测。
- 不修改 `data/rules/lexicon.json`（受保护）。
