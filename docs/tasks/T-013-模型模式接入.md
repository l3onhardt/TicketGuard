## 目标

T-012 做好了模型复核的纯函数。这张卡把它接成能用的产品：`tg.exe` 自己启动本机的模型程序、问完就关；用户可以选规则模式或模型模式；报告页交代清楚“模型复核做了没有、它怎么看”。

设计依据：`docs/decisions/0008-模型模式与harness.md` 第 1、4、5 节，**先读**。

## 接口（照写）

### `rust/tg/src/model.rs`（新文件，`main.rs` 里 `mod model;`）

```rust
/// 一个正在运行的模型程序。离开作用域时结束它。
pub struct Model { child: std::process::Child, port: u16 }

impl Model {
    /// 核对文件 → 启动模型程序（只听本机）→ 等它就绪 → 自检。`dir` 是模型目录。
    pub fn start(harness: &Harness, dir: &Path) -> Result<Model, Error>;
    /// 提问一次：发请求正文，拿回应答正文。
    pub fn ask(&self, body: &str) -> Result<String, Error>;
}
impl Drop for Model { /* kill + wait */ }
```

### `report.rs` 新增三个常量

```rust
pub const MODEL_ROW: &str = "模型复核（措施是不是只是写法不同）";
pub const MODEL_OFF_RISK: &str = "措施换了说法可能被报成缺少。";
pub const MODEL_OFF: &str = "这次是规则模式，没有请模型复核。措施换了说法可能被报成缺少。";
```

## 规则（由规划者确定，不要改）

### `Model::start`

按顺序，任何一步失败就返回 `Error`（消息照写）：

1. `server = dir.join(&harness.server)`，不是文件 → `找不到模型程序 {路径}`
2. `weights = dir.join(&harness.model)`，取不到元数据 → `找不到模型文件 {路径}`；字节数不等于 `harness.model_bytes` → `模型文件 {路径} 的大小不对（应为 {model_bytes} 字节，实际 {size} 字节），可能没有拷贝完整`
3. 挑端口：`TcpListener::bind((Ipv4Addr::LOCALHOST, 0))`，记下 `local_addr()` 的端口后放开。失败 → `本机没有可用的端口（{err}）`
4. 启动 `server`，参数逐个是：`-m {weights} -t {threads} -c {context} -np 1 --host 127.0.0.1 --port {port} --offline --no-webui`。标准输入、输出、错误都接 `Stdio::null()`。失败 → `模型程序启动失败（{err}）`
5. 等就绪，每 300 毫秒看一次，最多 180 秒：
   - `try_wait()` 发现它已经退出 → `模型程序启动后自己退出了（模型模式需要 Windows 10 以上的 64 位系统）`
   - 连 `(Ipv4Addr::LOCALHOST, port)`，`http(&mut stream, "GET", "/health", "")` 得到状态码 200 → 就绪。连不上、别的状态码、`http` 报错都算“还没好”，接着等
   - 超时 → `模型加载超过 180 秒还没有就绪`
6. `ticketguard::harness::selfcheck(harness, &mut |body| model.ask(body))?`

第 5、6 步失败时也要结束已经启动的进程（先建好 `Model` 再等，靠 `Drop`）。

### `Model::ask`

连 `(Ipv4Addr::LOCALHOST, port)`，读超时设 120 秒，`http(&mut stream, "POST", "/v1/chat/completions", body)`。io 错误 → `和模型程序通信失败（{err}）`；状态码不是 200 → `模型程序拒绝了提问（状态码 {status}）`；否则返回正文。

### 网络只能连本机（门禁会查这个文件的全文）

- `std::net` 只能出现在 `rust/tg/src/model.rs`。
- 每一处 `connect(` / `bind(` 都要和 `Ipv4Addr::LOCALHOST` **写在同一行**（`cargo fmt` 之后仍然要在同一行；把地址存进变量再传会被门禁拦）。
- 不得出现 `127.0.0.1` 以外的 IP、`localhost`、`SocketAddr`、`ToSocketAddrs`、`UdpSocket`。

### `main.rs`：模式

`check` 新增选项 `--mode rule|model|auto`。取值顺序：命令行给了用命令行的；否则读环境变量 `TG_MODE`；再没有就是 `auto`。其它值 → `--mode 只能是 rule、model 或 auto，不能是 {值}`。拖放模式没有命令行选项，同样走环境变量和 `auto`。

模型目录是 `locate("models")`，设置文件是 `locate("data/harness.json")`。

| 模式 | 行为 |
|---|---|
| `rule` | 不碰模型，不读设置文件 |
| `auto` | 模型目录存在（`is_dir`）就按 `model` 走，否则按 `rule` 走 |
| `model` | 读设置（读不了是硬错误，照常往上传）→ 打印 `正在启动模型（第一次要等一会儿）…` → `Model::start` |

`Model::start` 失败**不是**硬错误：打印 `模型没有用上，这次只用规则：{原因}`，这次运行的每张票都记 `review.model = ModelUse::Failed(原因)`，照常出报告。

一次运行只启动一回模型：拖进来几张票，共用同一个 `Model`，全部审完再结束它。用一个三态的枚举表示“规则 / 模型已就绪（带着 `Model` 和 `Harness`）/ 没用成（带着原因）”，在 `cmd_check` 和 `run_dropped` 里各准备一次，传给 `check_ticket`。

`check_ticket` 里，`review_text` 之后：

- 模型已就绪：`second_opinion(&mut review, &templates, harness, &mut |body| model.ask(body))`。它返回错误时打印 `模型复核没有做成，这张票只用了规则：{原因}`，记 `review.model = ModelUse::Failed(原因)`，照常出报告（`second_opinion` 保证出错时没有改动 `review`）。
- 没用成：`review.model = ModelUse::Failed(原因)`。

`usage()` 里 `check` 那一行加上 `[--mode rule|model|auto]`，下面加一行说明：`--mode：rule 只用规则；model 规则之后再请本机模型复核；auto（默认）有模型就用`。

### `report.rs`

1. `group`：`CMP-REWORDED` 也归到“安全措施（对照典票）”。
2. 每条发现的 JSON 末尾加一个键 `second`：`finding.second` 是 `None` 时为 `null`，否则是 `{measure, same, p, says}`（键的顺序照写），`says` 是：
   - `same` 为真：`票面上的“{measure}”和典票这一条是同一类措施，只是写法不同。`
   - 否则：`这一栏里最接近的是“{measure}”，但它和典票这一条不是同一类措施。`
3. 清单里“安全措施（对照典票）”一行：没有 `CMP-MISSING` 但有 `CMP-REWORDED`（记作 r 条）时，状态 `found`，说明 `对照{场景}，有 {r} 类措施的写法和典票不同，见下方`。其余情况不变（有 `CMP-MISSING` 时仍只数 `CMP-MISSING`）。
4. 清单里在“安全措施（对照典票）”后面、“机器查不了的项目”前面，固定加一行，`name` 是 `MODEL_ROW`。记 n = 带 `second` 的发现条数，r = `CMP-REWORDED` 的条数：

   | `review.model` | status | detail |
   |---|---|---|
   | `Off` | `skipped` | `MODEL_OFF` |
   | `Failed(原因)` | `skipped` | `模型复核没有做成：{原因}。这份报告只用了规则，{MODEL_OFF_RISK}` |
   | `Done`，n = 0 | `checked` | `没有需要模型复核的事项` |
   | `Done`，n > 0，r = 0 | `checked` | `模型复核了 {n} 条疑似缺少的措施，没有发现只是写法不同的` |
   | `Done`，r > 0 | `found` | `模型复核了 {n} 条疑似缺少的措施，认为其中 {r} 条只是写法不同，已改成提示，见下方` |

5. 页面：发现卡片里，`second` 不是 `null` 时，在“典票上的写法”那一段后面、“依据”前面加 `<p class="second">模型的看法：{says}</p>`（转义）。样式加一条 `.second {background: #f0f4f8; padding: .5rem .75rem;}`。页面上不出现把握的数字，也不出现 `CMP-REWORDED`。

## 不做

- 不做重试、不做端口冲突后的再试、不缓存模型的回答、不让模型常驻。
- 不引入任何依赖；HTTP 就用 T-012 的 `http`。
- 不给模型程序的路径、端口、超时加命令行选项或环境变量（只有 `--mode` / `TG_MODE` 一个开关）。
- 不改 `eval`、`synth` 等其它命令。不把模型程序的日志存盘。
- 不改 `harness.rs`、`review.rs`、`schema.rs`（受保护）。
