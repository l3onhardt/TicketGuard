## 目标

读取 `data/rules/*.rules.json` 里的规则，对一张 `Ticket` 逐条执行，输出 `Finding` 列表。规则文件由规划者和业务人员维护（格式见 `docs/04-规则库规范.md`），引擎只认文件里写明的检查算子，不执行任意表达式。

## 接口（照写）

```python
# src/ticketguard/rules/engine.py
CHECKS: dict[str, Callable[[Ticket, dict], list[dict]]]   # 检查算子注册表（AGENTS.md 允许的唯一注册表）
def values(ticket: Ticket, path: str) -> list: ...         # 按路径取值
def load_rules(directory: str | Path) -> list[dict]: ...
def run_rules(ticket: Ticket, rules: list[dict]) -> list[Finding]: ...
```

每个检查算子的签名是 `(ticket, params) -> list[dict]`：返回空列表表示通过；每个 dict 是一处违规，里面的键用来填规则的 `message`（`str.format(**dict)`）。

## 规则（由规划者确定，不要改）

**取值路径 `values(ticket, path)`**，返回列表（没有值时为空列表，`None` 和空串都算没有值）：
- `fields.<键>` → `ticket.fields.get(键)`；
- `work_tasks.<键>` → 每个 work_task 里该键的值（跳过空值）；
- `people.<属性>` → 每个 Person 该属性的值（跳过空值），例如 `people.note`；
- 其他（如 `plan_start`、`crew_size`、`outage_scope`）→ `getattr(ticket, path)`。

**检查算子**（`CHECKS` 里只注册这 8 个）：

| 名称 | params | 违规条件 | 违规 dict 的键 |
|---|---|---|---|
| `required_field` | `fields: {路径: 中文栏目名}`（T-010 起；原为路径列表） | 某路径没有值（逐个） | `field`（中文栏目名） |
| `role_required` | `roles: [角色]` | `people` 里没有该 role 的人（逐个） | `role` |
| `roles_disjoint` | `roles: [角色A, 角色B]` | 同一个 name 同时出现在两个角色里（按姓名排序逐个） | `name`，`roles`（两个角色用 `、` 连接） |
| `before` | `chain: [路径...]`，`strict: bool` | 先丢掉没有值的路径，再对剩下的相邻两项比较（ISO 时间字符串直接比大小）：前者 > 后者，或 `strict` 为真且相等 | `a`、`b`（路径最后一个 `.` 之后的部分），`a_time`、`b_time` |
| `duration_max` | `start`、`end`（路径），`hours` | 两者都有值且时长（小时）> `hours` | `actual_hours`（用 `f"{h:g}"` 格式化），`hours` |
| `crew_count` | （无） | `crew_size` 有值且 ≠ 期望人数 | `actual`、`expected` |
| `regex` | `field`（路径）、`pattern`、`must_match: bool` | 对每个值：`re.search` 是否命中 ≠ `must_match` | `value`，另加 `evidence`（= 该值） |
| `lines_subset` | `field`（路径）、`within: [路径]` | `field` 各值抽出的线路（`entities.lines`）中，有不在 `within` 各值线路并集里的 | `lines`（多出的线路按字符串排序后用 `、` 连接），另加 `evidence`（`field` 各值用 `；` 连接） |

`crew_count` 的期望人数：取所有 role 为“工作班成员”的人；如果其中有人的 `note` 匹配 `(\d+)\s*人`（分组派工单写法，如“张三（第一组5人）”），期望人数 = 这些数字之和；否则期望人数 = 1 + 工作班成员人数。

**`load_rules(directory)`**：读目录下所有 `*.rules.json`（注意不是 `*.json`；同目录还有 `lexicon.json`），按文件名排序。每个文件是规则列表。逐条校验，失败抛 `ValueError`，消息里写出文件路径和规则 id：
- 必须有字段：`id`、`title`、`ticket_types`、`check`、`params`、`severity`、`message`、`basis`、`status`；
- `basis` 必须**恰好**有 `doc`、`clause`、`text`、`source` 四个字段；
- `check` 必须在 `CHECKS` 里；`severity` 必须是 `Severity` 的取值；`status` 必须是 `draft` / `reviewed` / `active` 之一。

**`run_rules(ticket, rules)`**：按规则顺序，跳过 `ticket.ticket_type.value` 不在 `ticket_types` 里的规则。对每处违规生成一个 `Finding`：
- `rule_id` = 规则 id；`basis` = `Basis(**rule["basis"])`；`confidence` = 1.0；`scenario_id` = None；
- `severity`：规则 `status` 为 `draft` 时一律是 `Severity.INFO`（草稿规则只做提示），否则用规则的 `severity`；
- `message` = `rule["message"].format(**违规dict)`；`evidence` = 违规 dict 里的 `evidence`（没有就是空串）；
- `needs_review` = `severity != Severity.ERROR`。

## 不做

- 不新增算子，不支持算子组合、条件表达式、规则继承。
- 不读取、不修改规则文件以外的任何东西；不缓存。
- 不在 `run_rules` 里做异常兜底。
