## 目标

主界面不再让用户选模式。页面对每张票先要“规则检查”的结果，再要“完整结果”；服务端在完整结果里自己决定要不要启动模型——规则没有报“可能缺少措施”就不启动。另外加一个接口，把随程序带着的成绩单（`data/accuracy.json`）交给页面。

设计依据：`docs/decisions/0010-一条流水线和成绩单.md`，**先读**。页面（`rust/tg/src/ui.html`）已经由规划者按新接口重写，受保护。

## 一、核心库 `rust/ticketguard/src/ui.rs` 新增一个函数

```rust
/// 从一份报告（`build_report` 的结果）里取出主界面要显示的几个数。
pub fn summary(report: &serde_json::Value) -> serde_json::Value;
```

返回（键的顺序照写）：

```json
{"number": "…", "level": "…", "headline": "…", "issues": 0, "notes": 0, "pending": 0, "reworded": 0}
```

- `number`：`report.ticket.number`；不是字符串或为空串时写 `未填写`。
- `level`、`headline`：`report.verdict` 里的同名键。
- 下面四个数都是数 `report.findings`：
  - `issues`：`severity` 不是 `info` 的条数；`notes`：`severity` 是 `info` 的条数。
  - `pending`：`rule_id` 是 `CMP-MISSING` 的条数；`reworded`：`rule_id` 是 `CMP-REWORDED` 的条数。

报告是程序自己生成的，结构不对属于内部不变量被破坏，用 `expect` 说明，不做容错。

## 二、`rust/tg/src/main.rs`：把 `check_text` 拆成三步

现在的 `check_text_with_source` 一口气做了“读数据 + 预审 + 模型复核 + 写报告”。拆成：

```rust
/// 读规则、模板、词表，预审一段票面文本。
fn review_ticket(text: &str, args: &Args) -> Result<(Review, Vec<Template>), Error>;
/// 按这次的模式处理模型复核（原来那段 match，原样搬过来，包括那句 println!）。
fn apply_mode(review: &mut Review, templates: &[Template], mode: &Mode);
/// 生成报告，写出 JSON 和 HTML，返回 (HTML 路径, 报告)。`source` 是报告里写的来源文件名。
fn write_report(review: &Review, templates: &[Template], name: &str, source: &str, out_dir: &Path)
    -> Result<(PathBuf, serde_json::Value), Error>;
```

`check_ticket`（命令行和拖放用）改成依次调这三个。`check_text` 和 `check_text_with_source` 删掉。**命令行和拖放的输出、报告内容不能变**（规划者会逐字节比对）。

## 三、`rust/tg/src/ui.rs`

### `POST check`

正文从 `{"name", "text", "mode"}` 改成 `{"name": 字符串, "text": 字符串, "stage": "rule" 或 "full"}`。格式不对仍然返回 `{"ok": false, "error": "请求的格式不对"}`。

1. `review_ticket(text, args)`。
2. `stage` 是 `full` 时：
   - 发现里**没有** `rule_id == "CMP-MISSING"` 的：`review.model = ModelUse::Done { asked: 0 }`。**不启动模型**（哪怕模型还没启动过；也不读设置文件）。
   - 有：模型还没启动过就 `start_mode("model")`（结果记下来复用，和现在一样只启动一回；它返回 `Err` 时整个请求返回 `{"ok": false, "error": 原因}`）；然后 `apply_mode(&mut review, &templates, 记着的那个模式)`。
3. `stage` 是 `rule` 时不碰模型（`review.model` 保持 `Off`）。
4. `write_report(&review, &templates, &name, &format!("{name}.txt"), 报告目录)`，其中 `name = safe_name(请求里的 name)`。
5. 任何一步失败 → `{"ok": false, "error": 原因}`。成功 → 把 HTML 路径记进报告列表，返回（键的顺序照写）：

   ```json
   {"ok": true, "name": "…",
    "number": "…", "level": "…", "headline": "…", "issues": 0, "notes": 0, "pending": 0, "reworded": 0,
    "model": "…", "model_note": "…", "report": "report/{k}", "saved": "…"}
   ```

   中间七个键就是 `summary(&report)`。`model` / `model_note` 按预审结束时的 `review.model`：

   | `review.model` | `model` | `model_note` |
   |---|---|---|
   | `Off` | `off` | 空串 |
   | `Done { .. }` | `done` | 空串 |
   | `Failed(原因)` | `failed` | 原因 |

同一张票的两个阶段写的是同一个文件名，后一次覆盖前一次，两次都进报告列表。

### `GET accuracy`（新）

读 `locate("data/accuracy.json")`，解析成 JSON，原样作为响应正文返回（`application/json; charset=utf-8`）。

- 读不了 → `{"ok": false, "error": "{路径}：读取失败（{err}）"}`
- 不是合法 JSON → `{"ok": false, "error": "{路径}：不是合法的 JSON（{err}）"}`

不校验里面的字段（页面按字段名取，缺了就不显示那一块）。

### 其它

`status`、`examples`、`report/{k}`、`quit`、口令和 Host 的核对、启动时打印的文字，都不变。

## 不做

- 不给“要不要用模型”加开关、选项或环境变量。
- 不做进度接口，不开线程。
- 不在运行时跑考题；成绩单只是读文件。
- 不改页面、报告页、`model.rs`、`harness.rs`、`review.rs`。
