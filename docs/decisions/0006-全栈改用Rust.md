# ADR-0006 全栈改用 Rust，工具链钉在 1.77.2（Windows 7 兼容）

- 状态：已采纳（2026-11-12，需求方定调“全栈 Rust，具体做法由规划者定”）
- 取代：ADR-0001 中“核心功能只用 Python 标准库”的部分。ADR-0001 的动机（依赖少、好过审、能离线打包）不变。

## 背景

- 需求方要求全栈用 Rust，对 Python 有明确的偏见；评判标准是“快、稳、好用”。
- 目标电脑很可能是 **Windows 7**（待核实位数和 SP1）。
- Python 路线在 Win7 上走不通：Python 3.9 起不支持 Win7，本项目代码要求 ≥ 3.10。
- 运行逻辑本身不大（Python 参考实现的运行路径约 800 行），移植成本可控。

## 决定

1. **产品用 Rust 实现**，源码在 `rust/`：

   | crate | 内容 |
   |---|---|
   | `rust/ticketguard` | 核心库：解析、实体、规则引擎、场景匹配、措施比对、报告、合成、评测 |
   | `rust/tg` | 命令行入口，产出 `tg.exe` |
   | `rust/tests` | 集成测试和基准数据 |

2. **工具链钉在 `1.77.2-x86_64-pc-windows-gnu`**（`rust-toolchain.toml`）。
   - 1.77.2 是标准 Windows 目标仍支持 Win7 的最后一个版本，1.78 起要求 Win10。
   - 用 gnu 而不是 msvc：gnu 工具链自带链接器，开发机不用装 Visual Studio。
   - 开发、测试、发布用同一个编译器，测过的和交付的是同一个东西。

3. **依赖白名单**（`tools/gate.py` 的 `ALLOWED_CRATES`，新增要先写 ADR）：

   | 依赖 | 用途 | 为什么不自己写 |
   |---|---|---|
   | `serde`、`serde_json` | 读规则、模板、词表，写报告 JSON | JSON 解析自己写容易出错，这是事实标准 |
   | `regex` | 票面解析、合成算子里的正则 | 同上 |
   | `fancy-regex` | 带断言的正则（实体抽取；规则文件里的 pattern 按 Python 方言写） | `regex` 不支持断言 |
   | `once_cell` | 正则只编译一次 | 1.77 的标准库还没有 `LazyLock` |

   连同间接依赖，`Cargo.lock` 里锁定了 23 个第三方包，全部是 MIT、Apache-2.0、Unlicense 或 Zlib 这类宽松许可。其中 `serde_derive`、`syn`、`quote`、`proc-macro2`、`unicode-ident` 是代码生成工具，按用途推断只在编译期运行。

4. **Python 参考实现不再加功能**，只作对拍基准。2026-11-12 需求方决定归档：`src/`、`tests/`、`tools/tg.py`、`tools/parity/` 搬到 `archive/`，不参与构建和门禁（见 `archive/README.md`）。

5. 红线 6 改为：**依赖走白名单**，核心功能只用上表的依赖；新增第三方依赖之前必须写 ADR，并确认它能在 1.77.2 上构建、能离线打包。

## 验证（2026-11-12，开发机）

| 项 | 结果 |
|---|---|
| 266 张合成票，Rust 与参考实现的报告 JSON、HTML | 逐字节一致 |
| 合成集评测报告 | 逐字节一致（检出 205/207，场景命中 264/266） |
| 由典票重新生成 21 个模板 | 与入库的内容一致 |
| 9 个变异算子能生成的全部样本（285 种） | 两边集合相等 |
| Rust 测试 | 43 个通过，含“依据原文逐字可查”和“21 张典票零误报” |
| `tg.exe` | 2.5 MB，单票约 22 毫秒（参考实现约 240 毫秒） |
| exe 的导入表 | 5 个系统 DLL、121 个函数，没有已知的 Win8 以后才有的函数 |

对拍过程中查出并修掉 5 处移植错误（措施栏切分、场景切分、`plan_swap`、`loc_strip`、报告渲染），还有一处是浮点数解析精度（已打开 `serde_json` 的 `float_roundtrip`）。

## 没有验证、没有做的

- **没有在真实的 Win7 机器上运行过。** 现有证据是编译器版本和导入表，不等于实测。
- **只出了 64 位程序。** 目标机如果是 32 位 Win7，要另加 `i686-pc-windows-gnu` 目标。
- **没有移植 docx / xlsx 读取**（参考实现的 `ingest/office.py`）。所以 `tg` 没有 `ingest` 命令，`check` 也只接受 `.txt`。从典票 docx 到 `data/interim` 这一步目前还要用 Python。补上需要解压和 XML 解析，要再写一份依赖 ADR。
- **没有移植** `decision/base.py`、`ingest/source.py`：这两个是没有被调用的接口占位。
- 工具链停在 2024 年 4 月的版本，以后拿不到编译器的更新。本工具离线运行、只读本地文本文件，影响有限，但安全审查时要如实说明。

## 后果

- 新依赖如果要求更新的编译器，就用不了，或者只能用旧版本。
- `tools/gate.py` 现在同时检查两套代码；Rust 侧加了 `cargo fmt --check`、`cargo test`、`cargo clippy -D warnings`、禁用写法和依赖白名单。
- 这次移植没有走任务卡流程（需求方要求先跑通），由 `tools/parity/lint_rust.py` 对全量 Rust 代码补做了禁用写法检查。之后的 Rust 改动恢复走任务卡。
