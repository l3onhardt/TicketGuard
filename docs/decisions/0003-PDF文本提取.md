# ADR-0003 PDF 文本提取（提议中，等内网实测结果再定）

- 状态：**提议中**
- 日期：2026-11-05

## 背景

工作票系统不能导出，只能打印。主输入渠道因此变成“打印成 PDF”。

Python 标准库不能解析 PDF，这和 ADR-0001“核心零第三方依赖”冲突。另外，典票库的 PDF 用 pdftotext 提取出来时，中文全部丢失：这是字体缺少 ToUnicode 映射造成的。

## 候选方案

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 附带 `pdftotext.exe`（Poppler） | 和 llama-server 一样，作为独立的可执行文件调用 | 成熟、快，有 `-layout` 模式保留版面 | GPL 许可（作为独立程序调用，不和我们的代码链接）；多一个要过审的组件 |
| B. 把 `pypdf` 源码放进项目 | 纯 Python、BSD 许可 | 能打包进 exe，不需要外部程序 | 对复杂表格版面的还原能力一般 |
| C. 不解析 PDF，改用全选复制或网页另存 | 零依赖 | 最简单 | 依赖系统能否全选复制，以及复制出来的顺序 |

## 待决条件

需求方在内网实测以下几点（**只汇报结果，不带出票面内容**）：

1. 打印对话框里有没有“Microsoft Print to PDF”，或者“另存为 PDF”。
2. 打印出来的 PDF 用阅读器打开后，能否选中文字；复制到记事本里，中文是否正常、栏目顺序是否正常。
3. 系统是网页版（在浏览器里打开）还是客户端软件。

如果第 2 条正常，就选 A 或 B，倾向于 B，因为可以零外部程序。如果第 2 条是乱码，就只能走 C 或 OCR。
