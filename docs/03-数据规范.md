# 03 数据规范

## 1. 数据来源分级

| 级别 | 内容 | 能否入库 | 能否发给外部 AI |
|---|---|---|---|
| L0 公开 | 合成数据、人工编造的样例 | ✅ | ✅ |
| L1 内部 | 典票库（标准样票、脚注、条款转述） | 原始文件不入库（在 `data/raw/`，被 git 忽略）；提炼后的模板和规则入库 | ⚠️ 尽量避免；需要时只发片段 |
| L2 敏感 | 真实工作票、人员信息、设备台账、拓扑数据 | ❌ 永远不入库 | ❌ 永远不发 |

L2 数据只能在内网、在正式立项之后，用于本地评测和微调。

## 2. 工作票：`Ticket`

定义见 `src/ticketguard/schema.py`。以配电第一种工作票为例，字段和票面栏目的对应关系如下：

| 票面栏目 | 字段 | 说明 |
|---|---|---|
| 编号 | `number` | 典票里的格式是 `YYYY-MM-P1-NNN`；带电作业票是 `P3`，其余票种的格式在 M1 统计后补充 |
| 工作负责人（监护人）、电话、单位和班组 | `people[role=工作负责人]`、`fields.电话`、`fields.单位班组` | |
| 工作负责人及工作班人员总人数 | `crew_size` | 规则：总人数 = 1 + 工作班人员人数（变更后要重新核对） |
| 计划工作时间 | `plan_start` / `plan_end` | 解析成 ISO 8601 格式 |
| 是否办理分组工作派工单 | `fields.分组派工单` | |
| 工作班人员 | `people[role=工作班成员]` | 要能识别“张三（新员工）”“赵七（厂家技术人员）”这样的身份标注 |
| 工作地点及任务 | `work_tasks[{地点, 任务}]` | 地点必须包含站名、线路名、双重名称、杆号 |
| 停电设备或线路名称 | `outage_scope` | |
| 调度或设备运维单位负责的安全措施 | `measures[category=…]` | 分为：应拉开关刀闸熔断器 / 应投切电源及二次回路 / 接地 / 标志牌 / 保留带电设备及注意事项 |
| 工作班组自行装设的接地线 | `measures[category=班组自装接地]` | 位置和编号成对出现 |
| 签发、会签、接收、许可 | `people[...]` 加 `fields.*时间` | “李某（张三代签）”要解析成 `Person(name=李某, proxy_for=…)`（具体谁代谁签，在 M1 时按票面写法确认） |
| 专责监护人 | `people[role=专责监护人]` | 带电作业必须设置 |
| 安全交代、间断、变更、延期、终结 | `fields.*` | 第一期只解析，不做深度校验 |
| 备注 | `fields.备注` | 里面常有班组自设的遮栏、标志牌等安全措施，也要解析到 `measures` |

## 3. 典票场景模板：`data/templates/<票种>/<场景ID>.json`

```json
{
  "id": "D1-S01",
  "ticket_type": "配电第一种工作票",
  "title": "单辐射开关后段线路停电作业（低压无可能来电的电源）",
  "source": {"doc": "2026.9典票库", "section": "二、场景1", "page": 12, "status": "有调整"},
  "applicability": "开关后段线路停电，低压侧无可能来电电源",
  "example_ticket": "…典票全文（人名已替换为占位符）…",
  "required_measures": [
    {
      "id": "D1-S01-M01",
      "category": "应拉开关刀闸熔断器",
      "pattern": "拉开 {线路}{开关} 及两侧刀闸",
      "must": true,
      "basis_ref": "BASIS-6.4.4"
    },
    {
      "id": "D1-S01-M04",
      "category": "接地",
      "pattern": "在 {线路}{杆号}{小号侧|大号侧} 装设接地线",
      "must": true,
      "note": "检修范围的各端都要封闭接地"
    }
  ],
  "risk_points": ["自动化开关合闸二次回路要断开（操作电源空开、合闸压板、PT 令克至少断开一种）"]
}
```

要点：

- `pattern` 里的 `{线路}` `{杆号}` 是占位符，比对前先把票面实体抽取出来，再代入。
- `must=false` 表示视情况才需要的措施，比如“若有光伏则……”。缺少这类措施时只报 warning。
- 人名一律替换成 `{工作负责人}` 这样的占位符，**前言里的编审人员名单不得进入模板**。

## 4. 合成样本：`data/synthetic/*.jsonl`

每行一个样本：

```json
{
  "id": "syn-000123",
  "base_scenario": "D1-S01",
  "mutations": [{"op": "drop_measure", "target": "D1-S01-M04"}],
  "ticket_text": "…变异后的票面…",
  "expected_findings": [{"rule_id": "CMP-MISSING", "measure_id": "D1-S01-M04", "severity": "error"}]
}
```

变异算子（M3 实现）：

| 算子 | 例子 | 期望检出 |
|---|---|---|
| `drop_measure` | 删掉一组接地线或一块标志牌 | 措施漏项 |
| `weaken_measure` | “断开操作电源空开、退出合闸压板”只保留一项，或者全部删掉 | 二次回路措施不完整 |
| `wrong_side` | 小号侧改成大号侧 | 疑似接地位置错误（warning） |
| `swap_type` | 本该用第一种票的作业改用第二种票 | 票种选择错误 |
| `time_shift` | 接收时间早于签发时间；动火有效期超过上限 | 时间逻辑错误 |
| `role_conflict` | 动火票的签发人兼任负责人 | 人员兼任 |
| `drop_monitor` | 带电作业没有设专责监护人 | 缺专责监护 |
| `rename_device` | 删掉设备编号，只留下名称 | 缺双重名称 |
| `paraphrase` | 换一种说法写同一条措施（**不是缺陷**） | **不应报错**，用来测误报 |

## 5. 黄金集：`data/golden/*.jsonl`

- 格式和合成样本相同，但每个标签都由懂业务的人（需求方）逐条核验，另外加 `"verified_by": "…", "verified_at": "…"` 两个字段。
- 只放 L0 数据（合成的，或人工编造的）。数量目标：第一种票 ≥ 200 张，其中 `paraphrase` 这类“干扰但合格”的票至少 30%。
